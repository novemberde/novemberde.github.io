How to use multiple Cursor or VSCode by language

March 3, 2025 2 min BYUN Kyuhyun

I’ve been using Cursor for a while and found it to be an excellent editor. However, when working on projects that require multiple programming languages, I often experience performance issues with the editor becoming sluggish. This reduces my productivity, so I’ve been searching for a way to use different editor setups for each language.

Using Profiles#

In Cursor (an editor based on VSCode), you can use Profiles to apply different settings for each language. This method doesn’t involve using different settings for each language directly, but rather uses different profiles to manage settings for each language.

Press cmd+shift+p and select >Profiles: New Profile... to create a profile:

Once created, press cmd+shift+p again and select >Profiles: Switch Profile... to choose the profile you created:

This allows you to set up an independent environment with a dedicated profile for your project.

Using user-data-dir#

I discovered that you can accomplish this by using the --user-data-dir flag. This flag allows you to specify a different user data directory for each language configuration.

For example, if you want to use Cursor for different programming languages, you can run these commands:

# Python Usage
cursor --user-data-dir=~/.cursor-python

# Go Usage
cursor --user-data-dir=~/.cursor-go

# Kotlin Usage
cursor --user-data-dir=~/.cursor-kotlin

This approach works great for using multiple editor configurations by language, and it’s compatible with VSCode as well.

However, I wanted to take this a step further. Rather than just having different configurations, I wanted to have different editor instances available directly from my command line.

Since I use Zsh, I set up the following aliases in my .zshrc file:

alias pcursor="cursor --user-data-dir=~/.cursor-python"
alias gcursor="cursor --user-data-dir=~/.cursor-go"
alias kcursor="cursor --user-data-dir=~/.cursor-kotlin"

Now I can use these commands to open Cursor with the appropriate configuration:

cd YOUR_DIRECTORY && pcursor
cd YOUR_DIRECTORY && gcursor
cd YOUR_DIRECTORY && kcursor

This solution allows you to use multiple Cursor or VSCode instances through the command line, each optimized for a specific language.

I’ve found that editor performance often degrades when using multiple plugins for many languages in a single instance. This approach of maintaining separate configurations prevents the editor from becoming slow, which has significantly improved my productivity. I hope it helps with yours as well.
